# Pilipili-AutoVideo 项目整体架构和技术栈分析

## 一、项目概述

**Pilipili-AutoVideo (噼哩噼哩)** 是一个全本地部署的端到端 AI 视频生成代理系统，通过自然语言描述即可自动完成从脚本规划到最终成片的完整流程。

### 核心定位
- **全自动工作流**: 一句话输入 → 完整视频输出
- **本地部署优先**: 数据隐私安全，完全可控
- **AI Agent 集成**: 标准化 Skill 接口，可被其他 AI 系统调用

## 四、核心模块架构

### 4.1 API 服务模块 (`api/server.py`)

#### 职责
- 工作流编排（5 阶段流水线）
- WebSocket 实时状态推送
- 人工审核暂停/恢复机制
- 项目管理（创建/查询/历史）
- API 连接器管理（配置各平台 Key）

#### 核心功能
```python
# 工作流状态枚举
class WorkflowStage(Enum):
    IDLE = "idle"
    GENERATING_SCRIPT = "generating_script"
    AWAITING_REVIEW = "awaiting_review"  # 人工审核关卡
    GENERATING_IMAGES = "generating_images"
    GENERATING_AUDIO = "generating_audio"
    GENERATING_VIDEO = "generating_video"
    ASSEMBLING = "assembling"
    COMPLETED = "completed"
    FAILED = "failed"

# 全局项目状态存储
_projects: dict[str, dict] = {}
_review_events: dict[str, asyncio.Event] = {}  # 暂停/恢复事件
_review_decisions: dict[str, dict] = {}         # 用户审核决策
```

#### 关键 API 端点

- `POST /api/projects/{id}/resume`: 断点续传
- `POST /api/settings/keys`: 更新 API Keys
- `POST /api/upload/reference`: 上传参考图
- `POST /api/analyze/upload`: 对标视频分析
- `GET /api/projects/{id}/download/video`: 下载成品视频
- `WS /ws/{project_id}`: WebSocket 状态推送

### 4.3 核心模块

#### LLM 脚本生成 (`modules/llm.py`)
- **功能**: 自然语言 → 结构化分镜脚本
- **支持模型**: DeepSeek/Kimi/MiniMax/Gemini/OpenAI/Ollama
- **核心数据结构**:
  - `Scene`: 单个分镜场景
  - `VideoScript`: 完整视频脚本
  - `CharacterInfo`: 人物信息
  - `ReferenceVideoAnalysis`: 对标视频分析结果

#### 图像生成 (`modules/image_gen.py`)
- **功能**: 为每个分镜生成高质量首帧关键图
- **支持模型**: Gemini 2.0 Flash/2.5 Flash/3.1 Flash
- **特性**:
  - 多参考图注入（角色一致性）
  - 模型fallback 机制
  - 会话级黑名单（避免重复失败）

#### 视频生成 (`modules/video_gen.py`)
- **功能**: 图生视频/文生视频
- **支持引擎**:
  - Kling Omni (多镜头、多参考图、首尾帧控制)
  - Kling v3 (高质量运动生成)
  - Seedance 1.5 Pro (口型同步、多角色)
- **智能路由**: 根据场景内容自动选择最优引擎
- **shot_mode**: 自动判断生成模式 (multi_ref/first_end_frame/t2v/i2v)

#### TTS 配音 (`modules/tts.py`)
- **功能**: 中文旁白生成 + 时长精确测量
- **支持模型**: MiniMax Speech 2.8 HD
- **特性**:
  - 时长精确到毫秒级
  - 音色克隆支持
  - 并发控制（避免RPM限速）

#### 视频组装 (`modules/assembler.py`)
- **功能**: FFmpeg 拼接 + 字幕烧录
- **特性**:
  - 精确裁剪到 TTS 时长
  - xfade 转场拼接
  - 音频混合（精确对齐）
  - SRT 字幕生成和烧录
  - Windows 兼容编码 (H.264 High Profile)

#### 剪映草稿 (`modules/jianying_draft.py`)
- **功能**: 自动生成剪映草稿项目
- **特性**:
  - 完整时间轴映射
  - 资源路径关联
  - 一键导入编辑

#### 记忆系统 (`modules/memory.py`)
- **功能**: 用户风格偏好学习
- **支持**:
  - Mem0 云端同步
  - 本地 SQLite 持久化
- **学习维度**:
  - 脚本风格偏好
  - 用户编辑模式
  - 评分反馈学习

## 七、核心设计亮点

### 7.1 音视频绝对同步
- **创新点**: 先生成 TTS 配音，精确测量时长（毫秒级），再用时长控制视频生成
- **优势**: 避免传统方案的音频视频错位问题
- **实现**: `update_scene_durations()` 函数

### 7.2 关键帧锁定策略
- **创新点**: Nano Banana 生成 4K 首帧，再用 I2V 生成视频
- **优势**: 保证画面质量和角色一致性
- **实现**: `generate_all_keyframes_sync()` + Kling Omni Reference API

### 7.3 数字孪生记忆系统
- **创新点**: Mem0 学习用户风格偏好，跨项目复用
- **优势**: 越用越懂用户，生成结果个性化
- **实现**: `modules/memory.py`

### 7.4 智能引擎路由
- **创新点**: 根据场景内容自动选择 Kling/Seedance
- **优势**: 充分发挥各引擎优势
- **实现**: `smart_route_engine()` 函数

### 7.5 人工审核关卡
- **创新点**: LLM 生成后暂停，用户确认后再调用付费 API
- **优势**: 避免浪费成本，提升用户掌控感
- **实现**: `awaiting_review` 阶段 + WebSocket 推送

### 7.6 断点续传机制
- **创新点**: 从已有资源继续生成，无需从头开始
- **优势**: 节省成本和时间
- **实现**: `/api/projects/{id}/resume` 接口

## 八、技术债务与改进空间

### 8.1 当前限制
1. **无用户认证系统**: API Key 明文存储在配置文件
2. **单机部署**: 不支持分布式扩展
3. **数据库简单**: 仅 SQLite，不支持高并发
4. **缺少日志系统**: 无结构化日志和监控
5. **测试覆盖不足**: 单元测试 18 个，E2E 测试较少

### 8.2 性能瓶颈
1. **API 限速**: MiniMax TTS 有 RPM 限制，需要并发控制
2. **视频生成慢**: Kling/Seedance 单分镜 2-5 分钟
3. **FFmpeg 编码**: 组装阶段耗时较长

### 8.3 功能缺失
1. **无权限管理**: 多用户场景无隔离
2. **无配额管理**: API 调用无统计和限制
3. **无告警机制**: 失败时无通知
4. **无版本回滚**: 项目生成历史无版本管理
