## 四、关键技术决策点

### 4.1 数据库迁移决策

**当前状态**: SQLite（单文件）  
**需求**: Phase 2 需要支持多用户 API Key 隔离

**建议路径**:

- **短期**: 扩展 SQLite schema，添加 `user_api_keys` 表
- **中期**: 迁移到 PostgreSQL（生产就绪，支持连接池）

### 4.2 认证模式决策

**当前状态**: 支持单用户兼容模式（`auth.enabled = false`）

**建议**:

- Phase 2 应移除单用户模式
- 始终要求认证（简化代码逻辑）
- 第一个注册用户自动成为 admin

### 4.3 前端状态管理

**当前状态**: 多个独立 Context（Auth、Theme）

**建议评估**:

- 是否需要全局状态管理（Zustand/Redux）
- 对话框状态管理优化（当前在 UserMenu 和 Studio 中重复）
- 是否引入 React Query 处理 API 状态

## 五、风险与挑战

### 5.1 技术风险

| 风险             | 影响                 | 缓解措施                           |
| ---------------- | -------------------- | ---------------------------------- |
| **SQLite 性能**  | 多用户下可能成为瓶颈 | 监控查询性能，准备 PostgreSQL 迁移 |
| **API Key 安全** | 泄露风险             | 加密存储、定期轮换、访问控制       |
| **第三方依赖**   | API 变更或不可用     | 故障转移机制、服务降级             |

### 5.2 资源风险

| 风险               | 影响         | 缓解措施         |
| ------------------ | ------------ | ---------------- |
| **OAuth 凭证获取** | 阻塞 Phase 2 | 并行推进其他功能 |
| **多用户测试**     | 覆盖不足     | 构建测试用户场景 |
| **性能测试**       | 未知瓶颈     | 提前建立基准测试 |

## 八、总结
